## 2. On-disk MP4 path

Verified on `01KQMZKRZVVEW3RBEFP82BK4MG` (latest done project):

```
projects/<project_id>/shots/<shot_id>/<external_ulid>.mp4
projects/<project_id>/shots/<shot_id>/reference.png
```

The inner MP4 filename is a fresh ULID generated by
`services/seedance.py:486` at save time, NOT the shot id. The DB stores
the full absolute path in `shots.rendered_video_path`, which the bridge
returns to the web client.

`lib/assets.ts:shotVideoUrl` was building `<id>/shots/<shotId>.mp4`
which never matches. Since the URL helper cannot derive the inner
filename from `(projectId, shotId)` alone, the function signature was
extended to accept `videoFilename: string`. P19a-1 callers will extract
the basename from `shot.rendered_video_path` and pass it in.

This is **Case B** from PHASE 2.5; the helper was edited; tsc clean
post-edit.

## 4. Deviations from the prompt

1. **Trash directory layout.** PHASE 1.2 of the prompt described the
   pattern as `_trash/<kind>/<id>/<timestamp>/` and pointed at
   `orchestrator.remove_character`. The actual code at
   `orchestrator.py:600-604` writes `_trash/<id>/<timestamp>/` (no
   `<kind>` namespace). PHASE 9.2 step 15 of the smoke test expects
   `_trash/shots/<sid>/<ts>/`, so I followed the prompt's documented
   pattern (with the `shots` namespace) for the new `remove_shot`. The
   existing `remove_character` was not changed (out of scope).
2. **db.py typed errors required a new base class.** The prompt said
   "add them as subclasses of the existing base error" but db.py had no
   typed errors at all, only `ValueError` and `sqlite3.OperationalError`.
   I introduced `DBError(RuntimeError)` as the base and four subclasses.
3. **`shotVideoUrl` signature change** in `web/src/lib/assets.ts`. The
   prompt called it a "one-line change," but the URL helper cannot build
   a correct URL from `(projectId, shotId)` alone because the inner
   filename is the seedance provider's ULID. I added a third positional
   `videoFilename: string` parameter so the helper stays a pure builder.
   `shotVideoUrl` is not yet called from any component (verified via
   grep across `web/src/`), so the signature change does not break
   anything.
4. **`source` and `reference_image_path` are projected by `sprite_show`
   but are not yet keys on the TS `Character` interface.** Projecting
   them is forward-compatible (extra JSON keys do not break TS at
   runtime; tsc does not error on the response shape because the
   bridge layer is `any`-typed). P19a-1 (or a follow-up) will extend
   the TS interface.
